What changes in the code

  • Only the board body swaps. KanbanView.vue:1368-1402 becomes a v-if/v-else. Header, both banners, the detail panel (1416-1452) and FilePickerDialog (1463-1474) stay shared.
  • New KanbanRowView.vue — groups item.tasks by kanban_column_id using the same filter as KanbanColumn.vue:185-188, and re-emits the same 16 events so KanbanView's pass-through block (1384-1401) is reused verbatim.
  • New KanbanTaskRow.vue (~45 lines) — wraps the existing sidebar row WorkspaceItemTaskRow.vue (32 px, same useTaskActions contract) and adds the kanban-only ⋯ open details button.
  • Group header is copied from KanbanColumn.vue:632-758 — chevron, name (click = inline rename), count badge, ⋮ menu (Rename / Sort tasks… / Delete / Run all agents) — with the drag handlers removed.
  • No new task UI, no new store mutation, no new endpoint.

URL + persistence contract

ParamValuesVerbDefault
layoutrows | columnsrouter.replacecolumns — stripped from the URL
  • Precedence: URL → localStorage (pabrik-kanban-layout) → columns. A deep link must beat the sticky preference.
  • Why replace: repo rule — "clicks write it (router.replace, not push, for tab switches)". push is reserved for opening a record (?detail=).
  • Why a new param: ?sorts= has a validated col_<id>:<field>:<dir> grammar — folding a mode into it breaks the parser.
  • Bug this plan also fixes: the ?sorts= watcher (KanbanView.vue:499-505) rebuilds the query from scratch and already drops ?detail=. It must be rewritten to use flatQuery() (710) or it will silently reset the layout too.
  • Collapse state is not URL state — it is a density preference, stored per board in pabrik-kanban-row-collapsed:<itemId>.

Decisions taken (and why)

  • No drag-and-drop in v1. Column DnD is drop-into-a-column, append-to-end (KanbanColumn.vue:520-535); there is no intra-column reorder anywhere. In a linear list the drop target is ambiguous and a wrong guess silently reorders a user's board. Row mode ships as read + open: click a row → task chat; ⋯ → detail panel (which already has a column picker).
  • No board-wide sort in v1. Row mode inherits each column's existing ?sorts= order. A board-wide sort needs a new ?rowsort= param + a board-wide fetch wrapper — follow-up.
  • No virtualization in v1. The board loads 10 tasks/column, so a 7-column board is ~70 light rows. Wrap in VirtualScroller only past ~500 loaded rows.
  • Counts are "loaded rows", not totals. The wire has no total_count (http_response.zig:617). The existing column badge has the same limitation, so the group header shows 12+ when hasMore.
  • Columns stays the default — the Playwright board test (tests/functional_ui/kanban_lifecycle_ui_test.py) keeps passing unchanged.
