5 · The forge marks — GitHub and GitLab, as SVG

The panel used to say 🔀 for both, which is the same class of bug as calling a GitLab merge request a “pull request” — the one helpers/forgeWording.ts exists to prevent in prose, thrown away again by the icon. These are the Simple Icons 24×24 marks (CC0-1.0), filled with currentColor so they inherit --semantic-text-dim rather than carrying a brand hex that would fight the kanagawa palette.

context band — 16px, next to --semantic-text-dim

#812 Open feature…main 12

The same component, one prop: <ForgeIcon :provider="prProvider" />. Unknown/empty provider falls back to GitHub — the same default forgeWording() uses, because pr_provider is empty on every session predating GitLab support.

legibility down the sizes the panel actually uses
16px · context band 28px · empty state
Both stay readable at 16px, which a single word (“GitHub”) would not — a label truncates inside a 200px panel, a mark does not.
the rule, now in AGENTS.md
No emoji as icons. If a standalone glyph's job is to identify an object or an action, it must be inline SVG. Emoji render at six different pixel sizes, are multi-colour, differ across Windows/macOS/Linux, and cannot be asserted on in a spec — only an SVG path can be.
