What changed

  • ①
    Red ⚠ icon (additive, top row). Sits next to the spinner — fires on top of the existing status (spinner / pulse dot / checkmark are mutually exclusive with each other, but the error indicator is separate because retries can happen mid-processing). 3-pulse ping animation on first appearance, then settles to a steady ring.
  • ②
    Red-tinted card border. Same --color-red token (matches the AgentErrorCard in ChatView). 55% alpha border + 25% alpha box-shadow ring so the card stands out at a glance across the board — even on a 6-column dense view.
  • ③
    Hover tooltip — headline + retry chip. Same parsing as AgentErrorCard.vue: [Retry N/M] → chip; error name + source → headline. Server-detail omitted on the kanban (would be too long for a 280px tooltip — the full detail still lives in the ChatView's AgentErrorCard).
  • ④
    Inline meta pill. Belt-and-suspenders affordance: same data as the icon but in the meta row, where users naturally scan for status. Shows retry 3/10 while retrying, swaps to a single workflow halted chip on the TooManyRetries bail.

Indicators on top row — priority

worker active?   → yellow spinner
   AND has error? → red ⚠ (additive)
needs review?    → orange pulse dot
stopped + reviewed? → green checkmark

Source wiring

// WorkspaceItemTaskCard.vue (and WorkspaceItemTaskRow.vue)
import { useAgentErrorStore } from '../../stores/agentError'
const agentErrorStore = useAgentErrorStore()
const hasAgentError = computed(() =>
  !!agentErrorStore.bySession[task.id]
)
const errorHeadline = computed(() => {
  const entry = agentErrorStore.bySession[task.id]
  return entry ? parseErrorHeadline(entry.content) : null
})

Why shared (kanban + sidebar)

Both WorkspaceItemTaskCard.vue (kanban) and WorkspaceItemTaskRow.vue (sidebar) already inject processingState from App.vue. Same pattern works for the agent error store. The sidebar row gets the icon too — users see "this chat has an error" even when the kanban board isn't visible.
