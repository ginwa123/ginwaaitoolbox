1 File tab with git badge CORE

Clicking a file in the Explorer opens it as a tab in the main panel. The tab carries the same status badge as the tree (M here), so the dirty state is visible even when the sidebar is collapsed.

2 Code / Diff toggle + change navigation

A segmented control switches between full-file Code and Diff (changed hunks only). The ↑ ↓ 3 / 7 stepper jumps between change blocks — same pattern as VS Code's "next change" (Alt+F5 style).

3 Line numbers + gutter change bars YOUR SCREENSHOT

Exactly what your screenshot shows: a line-number gutter, and a 4px color bar marking each changed line — ■ green = added, ■ orange = modified, ■ red arrow-tick = deleted line above. Unchanged lines have no bar. Clicking a line number copies the file:line reference.

4 Syntax highlighting ALREADY EXISTS

Token colors come straight from the existing codeHighlight.ts palette (keyword #8992a7, string #87a987, number #c4b28a, type #8ba4b0, function #8ea4a2) — the same theme as the in-app CodeEditor, so the file view and the editor agree.

5 Inline blame ("You, 2 hours ago") NEW BACKEND NEEDED

The blame annotation on the selected line shows author · relative time, right-aligned like your screenshot. There is no blame endpoint today — this needs one small addition: GET /api/git/blame?path=…&file=… wrapping git blame --porcelain. Blame loads lazily (only for visible lines) so it never blocks the file paint.

6 Unified diff view ALREADY EXISTS

View B renders @@ -old,count +new,count @@ hunk headers with − red / + green rows and old/new line numbers. Data comes from the existing POST /api/git/file/diffs endpoint — including its whole_file mode (git diff -U<all>), which returns every line with changes still marked: exactly what View A needs.

7 Status bar

Bottom bar summarizes the file: added / modified / removed counts, language, cursor position. Clicking a count jumps to the first line of that class.
