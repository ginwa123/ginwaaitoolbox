1 Where the numbers come from ZERO NEW REQUESTS

The counts are derived from diff text the panel already holds. Nothing is fetched for them:

  • Worktree rows read the folder-mode batch payload loadFullList already fetched for the center column (POST /git/file/diffs, folder: "").
  • PR rows read prFiles[].text — the PR diff already parsed by splitDiffByFile.

The spec pins this: one getGitChanges + one getGitFolderDiffs, and nothing else.

2 One counter, one regex — the row cannot disagree with the diff

countDiffLines() lives beside parseUnifiedDiff() and shares its hunk-header regex (hoisted to a module-level HUNK_HEADER). Two copies of that pattern drift the moment either is edited, and then the row's count stops matching the diff it opens.

A spec asserts the two agree on the same chunk — multi-hunk, rename header, \ No newline at end of file and all.

3 Why it does not build the line array

parseUnifiedDiff returns a ParsedDiffLine object per line. Reading two counters does not need an object per line of a 900-line file — on a 35-file list that is tens of thousands of objects to render two digits.

countDiffLines walks the same classification rules and allocates nothing.

4 UNKNOWN renders nothing — never +0 -0 THE DECISION

added / removed are number | null. null renders no chip at all.

A failed diff fetch must not read as "this file is unchanged" — which is exactly what +0 -0 would say. Both failure paths are pinned by spec:

fetch rejects → no chip anywhere, rows still render path absent from the payload → no chip on that row (the server only reports changed paths)

5 Row anatomy is unchanged

The count sits between the path and the stage/unstage button, so the status chip stays the first direct-child <span> of the row. SidebarDiffPanel.chrome.spec.ts selects [data-testid=…] > span to read the status letter, and a new spec pins that ordering.

House palette throughout: --color-green / --color-red, text-micro mono, tabular-nums so the digits do not jitter as they change. No emoji.

6 One shared component, four call sites

DiffCounts.vue is used by the PR list and all three worktree lists, so they cannot drift apart in colour, size, or spacing. It is the same pair of numbers the center diff header already showed (SidebarDiffView.vue), so a row and the diff it opens always agree.

Scope

Frontend only. No endpoint, no wire-format change, no backend change. vue-tsc --build, oxlint, eslint and prettier all clean; 101 sidebar/parser specs pass.

Three pre-existing ChatView failures (centerDiff, centerSync, tool-width) are unrelated — verified by stashing this change and re-running on the clean tree, where they fail identically.
