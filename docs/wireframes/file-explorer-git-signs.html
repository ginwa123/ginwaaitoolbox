1 Git status badges on every file CORE ASK

Each file row shows a colored badge from GET /api/git/changes (already exists — no backend change needed):

M modified (unstaged)   A staged new   D deleted   ?? untracked   R renamed

File names are color-coded by status (VS Code convention): modified files turn orange, untracked files go dim, deleted files get a strikethrough.

2 Branch header + dirty indicator CORE ASK

The header now shows the current branch with a leaf icon and a status dot: orange = uncommitted changes, green = clean tree. A refresh button re-runs git status.

3 Folder aggregate counts

Folders containing changed files show a count badge (e.g. tests 5) so you can see where work is happening without expanding every folder. The count rolls up all descendants.

4 Filter box

A search input at the top filters the visible tree by filename as you type — essential once a folder holds more than a few dozen files. Collapsed folders with matches auto-expand.

5 File type icons

Files get a Lucide icon by extension (.zig → code/aqua, .py → book/pink, .md → note/blue, images → image, folders → folder). Icons use stroke="currentColor" so they inherit the status color — a modified file's icon tints orange too.

6 Footer summary + legend

A compact summary bar counts each status class at a glance (3 modified · 1 staged · 1 deleted · 2 untracked) with a color legend. When the tree is clean it reads "Working tree clean" with a green dot.

7 Row polish

Consistent 24px row height, hover background, selected-row highlight, smooth chevron rotation on expand/collapse, and ellipsis truncation for long names. The full path moves from the footer into a hover tooltip on each row.

Data source & refresh

All git data comes from the existing /api/git/changes endpoint (staged / modified / untracked lists with index_status + worktree_status). The explorer builds a path → status map and joins it onto the folder listing. Refresh: on mount, on folder expand, on cwd change, and a 30s poll (same cadence as the existing sidebar git poll). No backend changes required.
