4 Wire & control flow

agent calls ask_user→ handle_tool inserts placeholder row + SSEs it (already exists) → execAskUser gate: human available?→ INSERT session_pending_question (Migration 087) → emit llm_full / role=ask_user / requested
card renders pending→ human picks staging→ POST /api/llm/session/:id/answer→ UPDATE row status=answered→ emit action=answered→ wait loop sees it within 100 ms→ tool result <status>answered</status> → agent resumes

Wire frames — no new event type

event: llm_full

{ "role": "ask_user",
  "action": "requested",
  "question_id": "q_1789509583247_ab12",
  "tool_call_id": "call_abc",
  "header": "Deploy target",
  "question": "Which environment should I deploy to?",
  "options": ["staging", "production"],
  "allow_free_text": true,
  "multi_select": false,
  "recommended": "staging",
  "expires_at": 1789510000 }
  // `answer` OMITTED while pending

Reuses the llm_full channel with a distinguishing role, exactly like subagent_progress — so there is no new named event and nothing to register in additionalEventTypes. A named event missed in registration is silently dropped by the browser before JS ever runs.

Three independent delivery paths

1. args      → question + options + recommended
                (renders from tool_calls_json alone)
2. SSE frame → live status: pending → answered
                (role="ask_user" on llm_full)
3. REST      → GET …/pending_questions
                rehydrates on page refresh

(1) means a missed/replayed event can never hide the question. (2) means the card flips state instantly. (3) means F5 mid-question keeps the card alive.

6 Answers to the four questions that shaped this

QuestionDecision
How does the card know the question before the tool returns?The placeholder row's arguments carry it, plus an ephemeral llm_full frame for status.
How does the loop pause?A DB poll loop (100 ms) that also polls the existing cancel flag — no condvar, restart-safe, deadlock-free.
How does the answer get back?POST /api/llm/session/:id/answer → row UPDATE → the loop's next poll returns.
What if nobody is there?Two-tier gate → unavailable instead of blocking.
