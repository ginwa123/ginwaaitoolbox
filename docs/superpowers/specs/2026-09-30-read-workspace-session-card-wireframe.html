1
The timestamp is a nanosecond epoch. 1790706338823948836 is created_at_nano aliased to created_at — llm_history.zig:2458 selects COALESCE(h.created_at_nano, '') AS created_at. A readable created_iso ('2026-09-30 19:53:35') exists in the same table and is never selected. Every row is showing a number a human cannot read.
2
The match highlight can never fire. The backend emits bare brackets — snippet(messages_fts, 0, '[', ']', '...', 10) (llm_history.zig:2454) — producing [portal]. parseSnippet (ReadWorkspaceSession.vue:371) only recognises the literals [match] / [/match]. Running the shipped parser against the real snippet above returns zero match segments, so every hit renders unhighlighted.
3
88% of the rows are noise. Measured on this exact query: tool 19,775 · assistant 2,568 · user 236. FTS indexes response_content, which for a tool row is the whole JSON envelope — so tool output matches as readily as human speech. The card offers no way to filter by role, even though the tool already accepts a role parameter.
4
No session identity, no action. The session name is an inert truncated <span> — there is no link, no open, no jump. And full_contents, which the backend returns verbatim when asked, is rendered nowhere in the component (zero occurrences of the key).

2 · Proposed shape

Three changes, in order of payoff: a filter bar that exposes the noise, grouping by session so 11,996 rows become ~12 conversations, and real highlights plus a real timestamp so a hit is legible at a glance. Every row becomes actionable.

4 · What the design needs from the backend

Four of the six fixes are frontend-only. The first one is the blocker: until the query returns a readable timestamp, the card cannot render one.

#ChangeSideEvidence / citation
1Return created_iso (or format the nano epoch) instead of raw created_at_nano backendllm_history.zig:2458 selects COALESCE(h.created_at_nano,'') AS created_at; the readable created_iso column is already in the table and already populated. Same alias at :775, :794, :827, :846.
2Align snippet delimiters — either emit [match]/[/match], or have the card parse bare […] frontendBackend emits '['/']' (llm_history.zig:2454); parseSnippet (ReadWorkspaceSession.vue:371) expects [match]/[/match]. Existing specs pass only because their fixtures use the un-emitted format.
3Group hits by session_id with a session header row frontendsession_id + session_name are already on every hit (read_workspace_session.zig JsonHit). No wire change needed.
4Role facet chips with per-role counts; wire clicks to the existing role parameter frontendrole is already an accepted tool parameter. Counts are the point: they reveal that 19,775 of 22,579 hits are tool rows.
5Make each row / session header openable — link to the session's chat route frontendPrecedent: SpawnSubAgent.vue 👁 peek button + ChatView.vue onPeekOpenFull; the canonical URL builder is buildAppUrl({ workspaceId, chatSessionId }).
6Render full_contents frontendBackend returns it on message_ids; the key appears 0 times in ReadWorkspaceSession.vue. Bodies are fetched and thrown away.

Deliberately not in scope

· Excluding tool rows from the FTS index would fix the noise at the source, but it changes recall for every consumer of messages_fts — that is a backend decision, not a wireframe one.
· Changing the OR-join query semantics. The card should explain OR-join, not hide it.
· A new right-hand "read" panel. The peek panel already exists and re-embeds ChatView; reuse it.
