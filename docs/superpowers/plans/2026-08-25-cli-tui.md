# `nalar-tui` implementation plan

## Goal

Add an interactive, streaming, Claude-Code-style TUI chat client
(`nalar-tui`) to the nalar CLI package, powered by a new reusable Zig
`tui` module. Lives entirely inside `src/apps/cli/` and reuses the
existing `custom_http_client` and `helpers` modules.

## Why now

`nalarcli` today is a one-shot JSON CLI (see
`src/apps/cli/src/commands/send.zig`): a user types
`nalarcli send "hi"`, gets back a JSON blob, and has no way to see
streaming output or have a back-and-forth. The user asked for a
Claude-Code-style TUI that can stream.

## What changes

- **New module `tui`** at `src/apps/cli/src/tui/` (Bubble-Tea-style
  architecture: `Model.update(msg) -> Model`, `Model.view() -> Frame`,
  single render loop driven by `std.Io` events). Pure Zig, no
  dependencies.
- **New executable `nalar-tui`** (wired into the root `build.zig`
  alongside `nalarcli`) at `src/apps/cli/src/tui_main.zig`. Streams
  chat from the existing backend via the SSE channel + HTTP polling
  fallback.
- **`build.zig` additions**: `b.addModule("tui")`, `nalar-tui`
  executable, three steps: `run:tui`, `install:tui`, `test:tui`.
- **Tests**: inline `*_test.zig` for the terminal parser, frame
  differ, widget state machines, and app dispatch.
- **Docs**: a README section under `src/apps/cli/README.md` explaining
  the new binary, env vars, and `--no-sse` fallback.

## Non-goals

- No new HTTP endpoints (the backend already speaks SSE on
  `/api/events?channels=llm,queue` and serves the messages list on
  `/api/llm/session/:id/messages`).
- No persistent multi-session UI (a session picker is a follow-up).
- No slash-commands (Enter + Ctrl-C only in v1).
- No mouse / syntax highlighting / code-block rendering (plain text
  + word wrap in v1).

## Reuse (no new dependencies)

- **`custom_http_client`** (`src/modules/custom_http_client/`):
  - `custom_http_client.get`, `.post` for buffered calls.
  - `custom_http_client.openStream` + `ResponseStream.next` for SSE.
  - Both already used by `nalarcli`'s `events` command.
- **`helpers`** (project-wide):
  - `helpers.sanitize.sanitizeUtf8` to clean incoming message
    content (already used by `session_messages_get.zig`).
  - `helpers.terminal` (if it exists) — otherwise copy the
    `tcgetattr`/`tcsetattr` snippet into the new `tui/terminal.zig`.

## Risks and mitigations (re-stated from the spec for visibility)

1. **Terminal-state corruption on crash.** All raw-mode + alt-screen
   transitions go through `Program.run()`, which wraps the body in a
   `defer` that always restores the cooked terminal mode. Unit-tested
   by injecting a synthetic crash mid-loop.

2. **SSE drop mid-stream.** `transport.openEvents` catches
   `custom_http_client.Error.ConnectionClosed` and falls back to
   polling for the rest of the session. App state has a single
   `transport_mode: enum { sse, poll }` flag that flips on the first
   drop.

3. **C-varargs `ioctl` wrapper incompatibility.** The project already
   uses `std.os.linux.ioctl` directly for Linux native builds
   (precedent: see `src/modules/custom_http_client/src/...` for any
   `ioctl` use). On macOS we go through `std.c.ioctl` (varargs).

4. **Backwards-incompatible SGR.** v1 emits only `[0m`, `[1m`, `[2m`,
   and 8-color codes — all in the VT100 spec since 1979. No
   truecolor.

5. **CI non-tty.** `Program.run()` detects non-tty stdin and prints
   "nalar-tui requires a TTY; use --help" + exits non-zero. No crash.
