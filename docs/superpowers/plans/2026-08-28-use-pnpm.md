## Steps

### 1. Lockfile conversion
- `pnpm import` in each `package.json` directory.
- Delete the resulting `package-lock.json` (pnpm doesn't use it; it's
  stale metadata once `pnpm-lock.yaml` exists).
- Verify `pnpm-lock.yaml` is produced for both webapp + mcp.

### 2. Workspace `.npmrc`
- New file at repo root.
- `node-linker=hoisted` so vite + vue-tsc + eslint plugin chain
  resolve sibling node_modules paths the npm way (flat layout, no
  `.pnpm/` symlink indirection at the top level).
- `engine-strict=false` so a developer's Node 22.18.x doesn't fail
  on the webapp's `"engines": { "node": "^20.19.0 || >=22.12.0" }`.
- **NO** `onlyBuiltDependencies=esbuild` here — pnpm 11 ignores that
  line in `.npmrc` (the legacy field path was `package.json#pnpm.onlyBuiltDependencies`,
  also removed in pnpm 11). The actual allowlist lives in `pnpm-workspace.yaml`.

### 3. `pnpm-workspace.yaml` (mcp_hello_world only)
- pnpm 11 auto-creates a skeleton `pnpm-workspace.yaml` with
  `allowBuilds: esbuild: set this to true or false` whenever it sees
  a postinstall script it wants the user to approve. mcp_hello_world
  triggers this because vitest 2's transitive esbuild dep needs its
  postinstall to download the platform-native binary.
- Set `allowBuilds.esbuild: true` to approve.
- The webapp does NOT trigger this (vitest 4 marks esbuild optional),
  so no `pnpm-workspace.yaml` is needed there.

### 4. `build.zig` — mcp-hello-world chain
3 commands:
- `mcp_pnpm_install`: `"pnpm", "install", "--frozen-lockfile"` (replaces
  `mcp_npm_install` = `"npm", "install", "--no-audit", "--no-fund"`).
- `mcp_test`: `"pnpm", "test"`.
- `mcp_build`: `"pnpm", "run", "build"`.

## Notes
- pnpm's `--frozen-lockfile` is the equivalent of `npm ci` (fails if the
  lockfile would be modified). With `node-linker=hoisted`, the layout is
  flat like npm.
- pnpm 11.x is fully compatible with the existing package.json scripts
  (vitest, vue-tsc, tsc, vite all work — they're just scripts run via
  `node_modules/.bin/`).
- pnpm/action-setup@v4 works on Linux/macOS/Windows self-hosted runners.
- The postinstall allowlist syntax moved between pnpm versions:
  - pnpm ≤ 9: `package.json` → `"pnpm": { "onlyBuiltDependencies": [...] }`
  - pnpm 10: deprecated the `pnpm` field
  - pnpm 11: moved to `pnpm-workspace.yaml` → `allowBuilds: { ...: true }`
- `node-linker=hoisted` is a workspace-level setting (in `.npmrc`); pnpm
  reads it correctly across all sub-projects.
