# pwsh tool — PowerShell exec with the **same LLM-facing interface** as bash

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **⛔ DO ALL WORK IN A GIT WORKTREE — never on `main`.** See **Task 0 — Worktree setup** below. Project convention: every feature/refactor ships via a PR from `worktree/<topic>`. The kanban card moves to `merged` only after the user merges the PR.

**Goal:** Add a new agent tool `pwsh` that runs PowerShell Core (`pwsh`) commands, **with the identical JSON schema as the existing `bash` tool** (same fields, same types, same required-ness, same output envelope shape). The LLM can call `bash` or `pwsh` interchangeably without learning a new contract — switching tools is just swapping the tool name. Future shells (`cmd`, `fish`, `zsh`, `nu`, …) drop in the same way.

**Architecture:** Extract the spawn-arg, reader-thread, byte-truncation, line-count, timeout, background-detach, self-kill, URL-encode, and XML-serialization pipeline out of `bash.zig` into a generic `shell.zig` module. `shell.zig.execute_shell(...)` takes an `argv_prefix: []const []const u8` (e.g. `&.{"bash", "-c"}` or `&.{"pwsh", "-NoProfile", "-NonInteractive", "-Command"}`). `bash.zig` and `pwsh.zig` become thin wrappers (~80 lines each) that supply ONLY the executable+argv-prefix, the tool name, the `AgentTool` schema, and the public re-export of `BashInput`/`BashOutput` and `PwshInput`/`PwshOutput` (which are identical struct shapes — make them `pub const = ShellInput` aliases so the wire schema cannot drift).

**Tech Stack:** Zig 0.16 (existing `bash.zig` + the existing `nalarcore.bash_tool` import surface), `std.process.spawn`, `std.json.parseFromSlice`, existing `nalarcore.tool_models` schema structs, existing `tools_wrap_output.wrapToolOutput`, existing `wrapToolOutput` test envelope, Zig `std.testing`. **No new dependencies.**

## Background — why a new tool when `bash` already exists?

Today the agent has one shell tool: `bash` (Linux/macOS) or `pwsh` via Windows path is not exposed at all. The user wants:

1. **Cross-platform scripting** — many workflows (notably CI scripts that the LLM reads back, .NET builds, Azure DevOps glifs, Windows registry edits) live in PowerShell. Forcing the LLM through `bash` to pipe PowerShell commands means `bash -c 'pwsh -Command "..."'` quoting hell.
2. **Same interface** = no new mental model — same `command`, `cwd`, `mandatory_timeout`, `max_output`, `stdin_data`, `background`, `max_lines`, `do_encoding` JSON shape. Same `<command>…</command> <stdout>…</stdout> <stderr>…</stderr> <exit_code>…</exit_code> <truncated>…</truncated> <timeout>…</timeout> <stdout_lines>…</stdout_lines> <stderr_lines>…</stderr_lines> <is_self>…</is_self>` output envelope. Identical `wrapToolOutput(... "pwsh" ...)` tool-name spacing in the LLM-facing envelope.
3. **Future-proof** — `cmd`, `fish`, `zsh`, `nu` can drop in as additional thin wrappers around `shell.zig` without copy-pasting the streaming / timeout / SIGKILL-pgid / shutdown-FD logic that bash has accumulated (840 lines as of 2026-08-14).

## Design Decisions (review before execution)

| ID | Decision | Why | Alternative rejected |
|----|----------|-----|----------------------|
| D1  | **Extract `shell.zig` first** — refactor `bash.zig` into a thin wrapper around a new generic `shell.zig`. | The user said "same interface". That means **one source of truth** for the wire schema, the timeout/streaming pipeline, the self-kill check, the URL-encode step, and the XML output envelope. Duplicating 840 lines for pwsh guarantees drift. | Pure copy-paste of bash.zig → pwsh.zig. Faster but every bash bugfix has to be backported; "same interface" is brittle the moment a patch lands in one file and not the other. |
| D2  | **`ShellInput` is the canonical struct** in `shell.zig`. `BashInput` and `PwshInput` are `pub const = ShellInput` aliases. Same for `BashOutput` / `PwshOutput` / `ShellOutput`. | JSON-schema fields and types MUST match exactly. Zig type aliases preserve structural identity — `std.json.parseFromSlice(BashInput, …)` and `std.json.parseFromSlice(PwshInput, …)` produce identical results. | Two separate struct types with the same fields — drift risk; the schema test from `create_kanban_task_test.zig:1051` would let you check `BashInput == PwshInput` but easy to forget. |
| D3  | **`shell.zig` is the canonical owner of `is_forbidden_command`, `encode_command_urls`, `wait_pid_bounded`, `status_to_term`, `read_loop`, the kill-pgid-and-reap-Victor, the byte+line truncation, the background `nohup` invocation, the per-stream buffer logic, and the `<command>…</command><stdout>…</stdout>…` XML formatter.** bash.zig keeps ONLY the bash-specific argv + the `bash` `AgentTool` schema definition. pwsh.zig keeps ONLY the pwsh-specific argv + the `pwsh` `AgentTool` schema definition. | Single canonical home for the bug-prone parts. New shells are ~80-line wrappers. | Two copies of the streaming pipeline — unreadable diffs and cross-shell inconsistency (e.g. macOS bash 3.2 subshell hang that was patched for bash but would silently regress pwsh). |
| D4  | **`argv_prefix` is opaque**. `bash.zig` passes `&.{ "bash", "-c" }` and `pwsh.zig` passes `&.{ "pwsh", "-NoProfile", "-NonInteractive", "-Command" }`. shell.zig appends the actual command string at the end. The `cwd`, `stdin_data`, `max_output`, `mandatory_timeout`, etc. semantics are identical across shells — only the argv layout differs. | CLI flag surface differs but the semantics of "run this command, capture stdout+stderr, enforce deadline, byte-cap output" is the same. Hiding the argv-prefix keeps the wrapper tiny. | Generic `ExecutableSpec` struct with typed fields — premature abstraction; pwsh's flag set will change in v8 (`-WorkingDirectory` exists in PS7+ preview). |
| D5  | **Self-kill check (`detect_self_kill`, `get_self_pid`) is shell-specific.** It currently checks `kill`/`exit`/target-PID patterns relevant to bash and (mostly) PowerShell too. We KEEP it in shell.zig as a shared helper for now; if PowerShell-specific patterns (e.g. `Stop-Process -Id $PID`) are reported later, split into `shell_selfkill.zig` with per-shell overrides. | Both shells terminate the process group on `kill` / `Stop-Process` targeting `$PID` / `$$`. The existing checks cover PowerShell's `Stop-Process` if invoked without `-Id`. Defer the PowerShell-specific patterns until a real bug report — YAGNI. | Per-shell selfkill vtable — premature; one regex covers both today. |
| D6  | **`URL encoding`** (the `encode_command_urls` that swaps `"url"` → `'url'` for bash so `?` & `&` aren't glob-expanded) is KEEP-SHARED, but the rationale document in shell.zig now notes it also helps pwsh (PowerShell also treats `?` as wildcard and `&` as call operator). | Both shells have the same foot-gun. | Strip out of pwsh — leaves a known bug for pwsh users. |
| D7  | **bash on Windows → `error.UnsupportedOS`** is removed from the shared `shell.zig`. Per-shell: bash.zig re-adds the Windows guard at the very top of `execute_bash` (the only place it makes sense — bash 3.2 is unreliable on Windows). pwsh.zig does NOT have the guard because PowerShell 5.1 (preinstalled on Windows) and PowerShell Core 7+ (cross-platform) both work. The shell.zig core assumes "this argv-prefix is callable from the host". | pwsh IS on $PATH on Windows by default (powershell.exe / pwsh.exe). Forcing UnsupportedOS would defeat the entire purpose of the new tool. | Keep the Windows guard in shell.zig — blocks pwsh on Windows, the user's primary need. |
| D8  | **`background` mode → `nohup` is bash-specific idiom.** pwsh does NOT have `nohup`. Replace with `Start-Process -NoNewWindow -RedirectStandardOutput` for pwsh's background path. | pwsh has no shell-builtin "detach" the way bash does; `Start-Process` returns the spawned process object immediately, which is the pwsh idiom. Putting this in `shell.zig` would mix two CLI styles. | Keep nohup in shell.zig for both — pwsh users get a confusing `nohup : The term 'nohup' is not recognized as a name of a cmdlet` error. |
| D9  | **Mandatory timeout semantics are shell-neutral.** shell.zig enforces the same wall-clock SIGKILL/KillProcess-grace-period → bounded-waitpid `Term` mapping for both. Self-imposed pwsh flag `-NoProfile -NonInteractive` matches the existing process-group kill semantics. | Timeouts are a property of "wrapping an arbitrary child process", not "running bash". Centralising avoids "pwsh times out 2 seconds later than bash on Linux" drift. | Per-shell timeout logic — drift risk. |
| D10 | **The `pwsh` tool description documents PowerShell-idiom command rules** (`Select-Object -First N` instead of `head -n N`, `Get-ChildItem` instead of `ls`, `Set-Location` instead of `cd`, `$PWD` instead of `$PWD` in pwsh, `Start-Sleep` instead of `sleep`). bash keeps its POSIX-idiom rules. Both share the `"start with timeout, end with head -n N"` macro-rule. | New users of pwsh tool deserve shell-correct examples. | D11 | **`pwsh` registers in BOTH `equips` AND `UNIFIED_TOOL_REGISTRY`** — every tool that calls `bash` should be able to call `pwsh` with no other code change. Default `equips()` list exposes both. Future toggle / per-sub-agent opt-out lives in `LlmConfig.profiles[].tool_overrides` (already supported for `web_search` / `set_git_worktree`). | Symmetry with bash is the goal. Exposing pwsh by default to every chat lets Windows users start using it without extra wiring. | Expose only in sub-agent context — defeats the "same interface everywhere" goal. |

## Global Constraints

- **TDD discipline**: every implementation step starts with a failing test, then minimal code to make it pass, then a commit.
- **Cross-platform**: every change must work on Linux, macOS, AND Windows. bash on Windows keeps its existing `error.UnsupportedOS` guard at the wrapper layer. pwsh works wherever `pwsh` (or `powershell.exe` alias on older Windows) is on `$PATH`. Tests that require pwsh skip via `if !std.process.hasPowershell() return;` helper (test helper, not runtime — runtime just lets spawn fail with FileNotFound).
- **No static-contract tests** — user rule (2026-07-29). All new tests are behavioural. The single existing static test in `tools_exec_show_preview_test.zig` is grandfathered.
- **Surgical patches** — don't refactor `bash.zig` beyond what's necessary to extract `shell.zig`. The bash self-kill detection list is **kept verbatim** in shell.zig, just moved physically, with the docstring updated to note "shared by bash + pwsh".
- **No new migrations** — `session_background_process` table is reused.
- **No port 8081** — smoke tests use port 8080.
- **Zig 0.16 anonymous-struct-literal gotcha**: when constructing optional-field structs (`ShellInput`, `ShellOutput`), initialize ALL fields explicitly. Same gotcha that bit `buildJsonAnthropicRequest` (`Agent.zig:1100`). Mirror that pattern verbatim.
- **Naming**: `ShellInput` / `ShellOutput` are the canonical types; `BashInput` / `PwshInput` / `BashOutput` / `PwshOutput` are `pub const = …` aliases in their respective wrapper files.
- **No `unused` lint regressions** — `shell.zig` may declare `pub fn`s that bash.zig uses but pwsh.zig does not; silence unused-when-reachable-with-pub-via-module.

const std = @import("std");
const builtin = @import("builtin");
const helpers = @import("nalarcore").helpers;
const schemas = @import("schemas.zig");

const selfkill = @import("bash_selfkill.zig"); // shared; covered by D5
const xmlEscape = helpers.xml_escape;

/// Canonical wire schema. BashInput / PwshInput in their wrappers are
/// `pub const = ShellInput` so the JSON contract cannot drift.
pub const ShellInput = struct {
    command: []const u8,
    mandatory_timeout: ?u32 = null,
    cwd: ?[]const u8 = null,
    max_output: ?usize = 20 * 1024,
    stdin_data: ?[]const u8 = null,
    background: bool = false,
    max_lines: ?usize = 1000,
    do_encoding: bool = false,
};

pub const ShellOutput = struct {
    command: []const u8,
    stdout: []const u8,
    stderr: []const u8,
    exit_code: i32,
    truncated: bool,
    timeout: bool,
    stdout_lines: usize = 0,
    stderr_lines: usize = 0,
    is_self: bool = false,
};

// Re-export types from the helper modules so per-shell wrappers don't
// have to reach across two imports. (Per-shell files only import shell.zig.)
pub const MandatoryTimeoutMissing = error{MandatoryTimeoutMissing};

/// POSIX `nanosleep(req, rem)` — explained in bash.zig's existing comment
/// at lines 23-40 of the original. We re-declare here so shell.zig is
/// self-contained for Windows-portable code paths.
const NanoSleepTimespec = extern struct { sec: c_long, nsec: c_long };
extern "c" fn nanosleep(req: *const NanoSleepTimespec, rem: ?*NanoSleepTimespec) c_int;

const KILL_GRACE_PERIOD_NS: u64 = 2 * std.time.ns_per_s;

// … everything else from bash.zig is moved here in subsequent tasks. Task 1.1
// only lands the SKELETON (types + the helper copies + the `execute_shell`
// stub that returns error.NotImplemented for now). All bash_test.zig
// behavioural tests still pass against the OLD bash.zig.
pub fn execute_shell(
    _allocator: std.mem.Allocator,
    _io: std.Io,
    _argv_prefix: []const []const u8,
    _input: ShellInput,
) !ShellOutput {
    _ = builtin;
    _ = selfkill;
    _ = xmlEscape;
    _ = NanoSleepTimespec;
    _ = nanosleep;
    _ = KILL_GRACE_PERIOD_NS;
    return error.NotImplemented;
}

                    while (log_path_start < stdout.len and log_path_start < log_start + 5) : (log_path_start += 1) {}
                    if (log_path_start < stdout.len) {
                        const log_path = stdout[log_path_start..];
                        const ts = std.Io.Clock.now(.real, io);
                        const started_at: i64 = ts.toSeconds();
                        background_process.save(db_ptr, allocator, sess_id, pid, parsed.value.command, log_path, started_at) catch {};
                    }
                }
            }
        }
    }

    const res = try pwsh_tool_mod.pwsh_result_to_string(allocator, pwsh_output);
    return res;
}

pub fn execPwsh(ctx: ToolExecContext, tc: agent.ToolCall) !ToolExecResult {
    const inner = try runWithContext(ctx.allocator, ctx.io, tc, ctx.db, ctx.session_id);
    // wrapToolOutput tool_name arg is "pwsh" — distinguishes from bash in the
    // LLM-facing envelope (frontend <ToolCallCard tool-name="pwsh">).
    const output = try wrapToolOutput(ctx.allocator, "pwsh", tc.function.arguments, true, null, inner);
    return ToolExecResult{ .output = output, .output_allocated = true };
}

## Pitfalls

> These are failure modes I want explicitly recorded so a future agent (or me, in a fresh context) doesn't re-discover them.

- **bash on Windows is intentionally broken** — moving the `if builtin.os.tag == .windows return error.UnsupportedOS;` guard out of `bash.zig` (Task 1.5) into `shell.zig` would ALSO break pwsh on Windows. Place the guard at the bash.zig wrapper layer (Task 1.5 + D7). pwsh.zig has NO Windows guard.
- **nohup is bash-idiom, not PowerShell-idiom** — the `shell.spawn_background` extraction (Task 1.6) hardcodes `nohup`. pwsh's background mode should call `Start-Process` instead. We chose to keep nohup in shell.zig for now (D8) and address PowerShell's `Start-Process` translation in a follow-up; pwsh's `background=true` will return `error.UnsupportedFeature` until then. Document this clearly in `pwsh_tool`'s description (Task 3.1) and add a follow-up TODO in `shell.zig`.
- **The dangerous str-pointer-in-arena gotcha from Zig 0.16** — when constructing optional-field structs (the Anthropic SEGV bug from `Agent.zig:1100`), `ShellInput` has 8 optional fields. Always initialize them via explicit `.field = null` or via the JSON parser, NEVER via `.{ .command = rc, .rest_left_blank = ? }`.
- **The mandatory-timeout check fires at the wrapper layer** — putting it in `shell.execute_shell` would mean BOTH bash and pwsh return `error.MandatoryTimeoutMissing` when omitted. The semantics are the same for both shells, so centralising is fine; just verify nothing short-circuits before reaching the check.
- **The `event_type` wire-format rule** (system prompt global rule) — we are NOT adding new SSE event types here. The pwsh tool uses the existing `llm_full` event with `tool_name='pwsh'`. If you ever add a separate `pwsh_full` event_type for streaming progress, FOLLOW THE 3-SITE RULE: backend emitter + frontend `additionalEventTypes` + frontend dispatch chain.
- **Fork bombs (`bash -c ':(){ :|:& };:'`) execute before mandatory_timeout fires** — the existing `isForbiddenCommand` rule engine is disabled (line 174) so this passes. We're not re-enabling the rules in this PR (D5). If a future task re-enables the rules in shell.zig, pwsh gets them too — desirable, but a separate PR.
- **PowerShell version skew** — PowerShell 5.1 (Windows-default) has different parameter names than PowerShell 7+ (`pwsh`). `-NoProfile` and `-NonInteractive` exist on both. `-Command` exists on both. We don't need to fork the argv per PowerShell version; the same prefix works. If a future bug reports that `-WorkingDirectory` (PS7+) is preferred over `$cwd` arg-fallback, that's a separate change.
- **`bash_test.zig`'s `if builtin.os.tag != .linux and builtin.os.tag != .macos` skip** — pwsh tests should skip when pwsh isn't installed (Task 3.2's `pwsh_available()` helper), NOT on platform — pwsh runs on Windows too.
- **`tools_exec_pwsh.zig`'s background-tracking parser duplicates `tools_exec_bash.zig`** — KEEP it duplicated for this PR. Following D3 + DRY, extract into a shared `parse_pid_log_from_stdout` helper in a follow-up.
- **`useStdout/.pgid = 0` and `std.posix.kill` are POSIX-only** — shell.zig currently builds on Windows because `tools_exec_bash.zig` already gated this; pwsh.zig inherits. If we ever add a Windows-specific child-kill path, do it behind the same `if builtin.os.tag` guard.
