## Scope Check (YAGNI explicit per task)

Each task has a "Non-goals" subsection. In short:

- **Scroll-key binding**: no Up/Down for scroll (Up/Down stay bound to input history). No scrollbar visualisation. No goto-line. No vim-style `g g` jumps.
- **Word wrap**: no soft line breaks inside paragraphs, no hyphenation, no full Unicode width awareness — naive byte-width word wrap. UTF-8 multi-byte runes are counted as 1 each (matches `writeText`'s existing column width assumption).
- **`<plain>` strip**: no `<markdown>` / `<html>` content rendering, just tag un-wrapping so the text shows. Multi-line content inside `<plain>...</plain>` is preserved verbatim (the viewport wraps if it overflows).
- **Remove user echo**: no "pending" placeholder, no optimistic UI — straight 500ms blank between Enter and the first SSE poll. If that lag becomes annoying later, the optimistic-UI option is a follow-up.

      ```zig
      /// Remove `<plain>`, `<markdown>`, `<html>` (and matching
      /// closing tags) while keeping the inner content. Returns an
      /// owned slice.
      pub fn unwrapContentWrappers(allocator: std.mem.Allocator, content: []const u8) ![]u8 {
          var out: std.ArrayList(u8) = .empty;
          defer out.deinit(allocator);
          try out.ensureTotalCapacity(allocator, content.len);

          var cursor: usize = 0;
          while (cursor < content.len) {
              const stripped = stripOneWrapper(content[cursor..]);
              if (stripped) |n| {
                  cursor += n;
                  continue;
              }
              try out.append(allocator, content[cursor]);
              cursor += 1;
          }
          return allocator.dupe(u8, out.items);
      }

      /// Returns the byte length to skip if `content` starts with a
      /// known content-wrapper tag (`<plain>`, `</plain>`,
      /// `<markdown>`, `</markdown>`, `<html>`, `</html>`), else
      /// null.
      fn stripOneWrapper(content: []const u8) ?usize {
          inline for (.{ "<plain>", "</plain>", "<markdown>", "</markdown>", "<html>", "</html>" }) |tag| {
              if (std.mem.startsWith(u8, content, tag)) return tag.len;
          }
          return null;
      }
      ```

### Task 3 — Word-wrap long lines in the viewport

**Files:** `src/apps/cli/src/tui/widgets.zig` (add `wrapText`, rewrite `Viewport.render` to use it, add 4 tests).

**Why:** `Viewport.render` writes each `Line` to one row with no word wrap. Anything longer than the terminal width gets clipped at the right edge. Long assistant replies (paragraphs, code listings) are unreadable.

**Constraints:**

- Naive BYTE width (1 char = 1 col). Matches the existing `Frame.writeText` behaviour; no Unicode column-width table.
- Wrap at the last space that fits; if a word is longer than `width`, hard-split at `width`.
- Wrap ONLY affects rendering. The underlying `Line.text` slice is unchanged (so scroll/recount logic stays simple).

      ```zig
      /// split at the last space that fits (or hard-split at
      /// `width` when the line has no spaces). Caller frees the
      /// returned slice AND each chunk via `allocator.free`.
      ```

      ```zig
      pub fn render(self: *const Viewport, alloc, width, height) !Frame {
          var f = Frame.init(alloc, width, height);
          var row: u16 = 0;
          var i = start;
          outer: while (i < end and row < height) : (i += 1) {
              const text = self.lines.items[i].text;
              const style = self.lines.items[i].style;
              const chunks = try wrapText(alloc, text, width);

                  if (row >= height) break :outer;
                  _ = f.writeText(0, row, chunk, style);
                  row += 1;
              }
          }
          return f;
      }
      ```

### Task 5 — Scroll via keyboard (PgUp/PgDn) AND mouse/touchpad wheel

**Files:** `src/apps/cli/src/tui/program.zig` (enable SGR mouse tracking on enter, disable on leave), `src/apps/cli/src/tui/key.zig` (parse SGR mouse wheel sequences → new `Key.wheel_up` / `Key.wheel_down` variants), `src/apps/cli/src/tui/widgets.zig` (small helper for wrapped-height accounting), `src/apps/cli/src/tui/app.zig` (intercept page + wheel keys in `handleKey`), `src/apps/cli/src/tui_main.zig` (help text).

**Why:** With word-wrap (Task 3) long replies fit the viewport, but multi-turn conversations still overflow. Scroll needs to support BOTH keyboard (PgUp/PgDn, the standard TUI convention) AND mouse/touchpad wheel (modern UX expectation — the user asked for both).

**Scope choice:** Scroll by VISUAL rows, not logical lines. Standard TUI convention. PgUp/PgDn move by one viewport-screen (height − 2). Wheel events move by 3 visual rows per notch — a sensible default that matches how most TUIs (lazygit, k9s, vim with mouse=a) handle wheel.

**Why a wrapped-height helper is needed:** Without it, `scrollUp(N)` would advance by N logical lines per press — unusably slow for wrapped text, where a single long line can be 5+ visual rows.

**Why the mouse support is small:** `key.zig` already has a working CSI parser (`\x1b[5~` / `\x1b[6~` etc.) — we add the same shape for `\x1b[<64;x;yM` / `\x1b[<65;x;yM` (SGR-encoded mouse wheel). `program.zig` already emits escape sequences on enter/leave — we add 4 more lines.

## Pitfalls

- **Don't break the viewport scroll math with wraps.** Naive scroll `+= 1` per logical line under-counts wrapped lines. Use the `wrappedHeightOf` helper from Task 5 for `scrollUp(N)` / `scrollDown(N)` too if you want precise scrolling — but for v1 the simplest is to keep `scroll_from_bottom` counting LOGICAL lines and accept the slight inaccuracy. Mark as TODO.
- **Mouse tracking MUST be enabled AND disabled on the same code path.** If `program.run()` returns early (e.g. raw mode fails), the `defer` block MUST still emit the disable sequences or the user's terminal is left with mouse tracking on (every mouse movement pastes garbage text). Test the failure path explicitly.
- **SGR mode requires CSI < format.** Older terminals send X10 mode (`\x1b[M` + 3 bytes encoded as `button+32, x+32, y+32`). We enable SGR (1006) on startup so the modern format is guaranteed — older terminals fall back to their default which may NOT be SGR. Document this trade-off; we don't support legacy X10 mice.
- **Mouse button 64/65 are the wheel only when no modifiers are pressed.** Shift + wheel sends button 73/72. We map 64/65 → `wheel_up` / `wheel_down`; modifier wheel events are ignored for v1 (return null from the parser).
- **Don't add tool whitelists in Task 4.** The temptation is to add `load_memory`/`save_memory`/etc. to the whitelist. RESIST — the primary field for those tools varies too much; the cleaner fix is joining `tool_call_id` on the assistant row (a follow-up). Fall back to empty header.
- **Don't change `stripThinkingTags` semantics in Task 2.** Keep it focused on `<think>`. Add a separate `unwrapContentWrappers`. Two helpers, clear responsibilities. The `render_msg` assistant branch calls both in order.
- **Don't show a "▍ pending" placeholder after Enter in Task 1.** The user explicitly said "no need send message user print". Optimistic UI is a separate UX decision — defer to a follow-up.
- **Scroll keys may also fire through `input.handleKey`** if the input isn't disabled. Always intercept page + wheel keys in `App.handleKey` BEFORE delegating. The current Up/Down keys go to the input widget for history nav — keep that.
