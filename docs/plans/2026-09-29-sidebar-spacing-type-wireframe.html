Wireframe — the sidebar's spacing & type scale

Task task_1790616057649_4  ·  Companion docs/plans/2026-09-29-sidebar-three-menus-wireframe.html (IA + row types)  ·  Plan docs/plans/2026-09-29-sidebar-three-menus.md
The sidebar is not neat. Everything below is measured from the source, not estimated: every value is the literal Tailwind class in the file. Five files, one panel, and they use nine different font sizes, four different left edges, and three different row heights.
The reason is not carelessness. There is no tailwind config and no size token — style.css defines ~50 colour variables and zero spacing or type ones. Every number below was hand-picked inside one component, and nothing anywhere reconciles them. This wireframe proposes the three tokens that are missing.

13 px for the row label is not arbitrary. The project row already uses text-[13px] (WorkspaceItem.vue:604) — it is the value two of the three row types are already at, and it sits between the 14 the chat rows use and the 12 the child rows use. Picking the existing value is what makes this a normalisation rather than a redesign.

The header, which is currently the worst offender

Today the workspace name is text-sm 14 px (WorkspaceSwitcher.vue:208) and Settings / Logout on the same 48 px line are text-xs 12 px (Sidebar.vue:1449). Two weights and two sizes sharing one row is the most visible single inconsistency in the panel — and it is the first thing anyone sees.

Proposed: the name takes the 13 px row-label size at weight 600, so it ties to the content below it; Settings and Logout drop to the 11 px meta size, so the eye reads name then actions. Same row, one hierarchy.

This is not purely cosmetic. A child chat today gets 16 px less text than a project row, and the screenshot's failure mode — seven rows all reading New Chat — is partly because the names are truncated down to nothing before the difference can show. Normalising the indent gives every child row 16 px more text than it has now. The tidier layout is also the more legible one.

Three more arithmetic errors, all from stacking
  • The + is 20 px in a 28 px box; the ↓ is 16 px in the same 28 px box. Two identical controls, one glyph four pixels larger. ProjectsList.vue:398 vs ChatsList.vue:941.
  • The gap between list rows (2 px) is smaller than the gap before a list (4 px). space-y-0.5 inside, space-y-1 above — the rhythm inverts at every section boundary.
  • Three hit boxes: 24, 26, 28 px. Project +/× are 26 (WorkspaceItem.vue:684), child pin/✎/× are 24 (WorkspaceItemTaskRow.vue:264), the section actions are 28. Adjacent rows therefore have adjacent targets of three different sizes, which is both untidy and a mis-tap risk.

None of these is a bug. All of them are the visible cost of having no scale to check against.

6 — Why it drifted: there is no scale to drift from

Root cause, verified

There is no tailwind.config.js in src/apps/desktop. Tailwind is therefore running on stock defaults, and src/apps/desktop/src/style.css defines roughly fifty colour variables (--color-violet, --semantic-text-dim, …) and zero spacing or type variables.

That is the whole story. Colour is centralised and reconciled; geometry is not centralised at all. So py-2.5 in one file and py-2 in the next is not carelessness — there is nothing for either of them to be wrong relative to. The fix is not to correct nine numbers. It is to give the panel the token layer colour already has.

And a test contract that does not exist

ChatsList.vue:911 says, in a comment:

"Contract protected by sidebarSpacing.spec.ts — the exact class string below is grep-matched: 'class="px-3 py-2.5 flex items-center gap-2 w-full text-left hover:opacity-70 transition-opacity shrink-0 border-b border-[--color-border]/40"'"

That file does not exist. A repo-wide search for sidebarSpacing returns exactly one hit: the comment itself. The class string is locked by nothing, and the comment that says otherwise actively misleads the next person who wants to change py-2.5 into py-2.

The fix for this wireframe should be a real test that asserts the token values — not a grep of a class string, which pins today's inconsistency in place forever.

7 — Decisions

Proposing
  1. D12Four spacing tokens — --sb-gutter 12, --sb-row 32, --sb-indent 12, --sb-hit 24 — added to style.css beside the existing colour variables, not a tailwind.config.js. Rejected: a Tailwind config, because the repo already standardised on CSS vars and adding a second token mechanism is worse than extending the first.
  2. D13Three type sizes. 11 section / 13 row label / 11 meta, plus a fixed 12 px icon glyph. 13 because two of the three row types already use it.
  3. D14The nav's p-3 is deleted. This is what actually removes the 8 px step at the top of the panel; the header and New Chat move 16 → 12.
  4. D15Every row is 32 px, including RECENT. That changes :default-item-height on the VirtualScroller from 48 to 32 — see T0.
  5. D16Both section headers become identical: same 28 px height, same 12 px title, same border-b. Rejected: dropping the border to match PROJECTS — a rule between two peer menus is what keeps the boundary legible.
  6. D17The stale sidebarSpacing.spec.ts comment is deleted and replaced by a real spec that asserts the four token values. Rejected: writing the grep test the comment describes — it would enshrine py-2.5 as correct.
Still open
  1. Q4Does the header text move in by 4 px? D14 puts every label at 12 px, so Settings, Logout and New Chat shift left from 16 → 12. Recommendation: yes. Twelve is the value most of the panel already uses and it is what makes the single edge possible. The alternative — moving the lists out to 16 — spends the same 4 px somewhere else and leaves the list rows 8 px wider than they are now.
  2. Q5Do RECENT rows drop 48 → 32 px? They carry a git badge, a name, a time pill and a spinner. 32 px holds all four, and the saving shows up as more projects visible without scrolling. Recommendation: yes — 48 is the one row height that exists for no reason other than that it was the first one written.
  3. Q6Is 13 px too small for a project name? A project is the biggest object in the panel and it would render at the same size as a chat under it. The alternative is 14 for projects and 13 for chats, which re-introduces the two-size hierarchy this wireframe exists to remove. Recommendation: 13 everywhere, with hierarchy carried by the glyph and the indent — which is what the companion wireframe adds in T1.

Nothing in §1–§6 depends on an answer. Q4 moves four pixels, Q5 moves sixteen, Q6 moves one size.

8 — Explicitly not in this wireframe

  • Colour. The colour layer is already centralised and already reconciled. This wireframe changes no colour value.
  • The main content area, the appbar, the right sidebar. The sibling card "3 mode workspace items have different appbar" covers the appbar; the same token file should serve it later, but nothing here touches it.
  • Any change of meaning. Every proposal here is a change of geometry and type. The IA work — row types, breadcrumbs, glyphs, the search question — lives in the companion wireframe.
  • The right rail's or the top bar's spacing. Same reason: a token file is worth more than a fix, and a token file scoped to the sidebar is landable today.
