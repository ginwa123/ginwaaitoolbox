Wireframe — Android drawer · Recent gets a See-all destination

The drawer keeps five chats and everything else moves behind a See all chats › button at the bottom of the section. Tapping it closes the drawer and opens a new full-screen page that lists every chat in the workspace and pages on scroll. This is the shape the workspace-item kanban already uses, copied end to end: five rows inline, a button, a page behind it.

Changed The recents request goes back to limit=5 (RecentsApi.DRAWER_PREVIEW_ROWS, the same constant name ProjectsApi uses) so the drawer paints exactly what it shows. The full list is fetched by the new page at RecentsApi.CHATS_PAGE_LIMIT = 20, the way a project's chats are fetched — so paging cost is unchanged for the project shape and newly spent only where the reader actually asked for it.

The header's count keeps saying the server's total (30), not the five on screen, so a capped section still reports what is in it. See all chats › carries no count — same rule as the project's, for the same reason: the page behind it is what has the honest number.

3 · Why the page is a destination and not a taller drawer

  • The drawer has one scroller and two sections. Thirty rows of chat titles put Projects — the part of this drawer people navigate by — below the fold, and the last thing a reader wants from opening a drawer is to land in the middle of a list they did not scroll to.
  • A list that grows under your finger is not a list you can aim at. Tapping a chat is a positional act; a row that moves between two glances is a mis-tap.
  • The same reason the project row is not a destination either. A project row filters in place; the chat list is a place to go.
  • It is the shape the project already ships. Five inline, a See all chats › button, project/{workspaceId}/{itemId} behind it — page, filter, and the drawer all in agreement. Copying it end to end is why the two sections cannot drift apart.

4 · The wire

What changesDetail
RecentsApi.DRAWER_PREVIEW_ROWS New, = 5. The name mirrors ProjectsApi.DRAWER_PREVIEW_ROWS so the two sections say the same thing with the same words. The drawer requests exactly this many rows, so the composable renders chats as-is — there is no second, hidden cap in the UI to drift from the request.
RecentsApi.CHATS_PAGE_LIMIT 30 → 20, matching ProjectsApi.TASKS_PAGE_LIMIT. It is the page size for the new full-screen list. A workspace of thirty chats is two round trips on a screen the reader chose to scroll, rather than one thirty-row payload the drawer never shows.
Route chats/{workspaceId}, a sibling of chat/{sessionId} — not nested under it, or Back from a chat would pop the list. Deep link pabrik://chats/{workspaceId}. One id, not two: /api/session?workspace_id=… needs only the workspace, unlike the project's nested item endpoints.
Endpoint None. Same GET /api/session?sort_by=updated_at&direction=desc&limit=…&workspace_id=…, the same next_cursor round-trip. Only limit changes per caller.
HomeUiState isLoadingMoreChats and hasMoreChats come back — but they now feed the button's honesty and the new screen's footer, never a drawer scroll. The cursor and the load-more job live on in the ViewModel, used by the screen only.
Deleted toggleRecentsShowAll, isRecentsShowAll, the snapshotFlow paging watcher in the drawer, and the "Show fewer" half of the old toggle row. The new page gets a new drawer-free latch, exactly as ProjectChatsScreen does.
Not mirrored The project screen's + in the app bar. This page has no project to create in: the drawer's New Chat creates in the workspace's default project, and putting that on a full-screen list needs a decision of its own. Left out on purpose, not forgotten.

5 · Decisions a reviewer still has to answer

#QuestionRecommendation
Q1Should the button carry the count — "See all 25 more chats"? No. The project's does not, for a recorded reason: the page behind the button is what has the honest number, and a count in the drawer is a second place for it to go stale.
Q2Should the button's page be reachable from the chat route's drawer too? Yes, from both. It is the same drawer, so it must offer the same destination — the same reason the section fold is shared between them.
Q3What does the page's app bar do about creating a chat? Nothing for now. The project screen's + opens a flow scoped to one project; there is no equivalent here without inventing a "which project" question the drawer already answers for itself.
