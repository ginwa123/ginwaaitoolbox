Wireframe — making the kanban row readable

Task task_1790442547646_6 · design only — no code changed. Row mode already exists and works (?layout=rows, shipped in 31dfa31c). This wireframe is about the reading problem: today a row is a 32 px line of 12 px dim-grey text with three permanent icon buttons competing for attention, and zero metadata. Two 200-row groups look like a wall of identical lines.

The change: promote the row from a label to a two-line record — name at readable contrast, a metadata line (time · branch · tags · status) beneath it, a coloured status rail on the left edge, hairline separators so a long group is countable, and action buttons that only appear on hover. Frontend only — no backend, no new endpoint, no new data. Every field shown already ships on the Task payload that the board is already fetching.

Row anatomy — the 9 changes

make the kanban row, more readble
awaiting review · ⑂ worktree/make-the-kanban-row-more-readble-… · 12m ago
📌✎⋯✕
1
Name at full contrast, 13 px. Today the row name is 12 px / #7a8382 on #1D1C19 = 4.38:1 — it only clears AA for large text, and this is 12 px body copy. Proposed 13 px / #c5c9c5 = 10.17:1. Same words, 2.3× the contrast. This is the single biggest readability win and it costs nothing.
2
Status rail on the left edge. A 3 px bar, full row height, coloured by state — awaiting review · agent error · reviewed · agent running. Now you can scan a 110-row group down the left edge only and find the one that needs you.
3
Metadata line. Time, git branch, tag chips, status — under the name, 11 px / #a6a69c (6.94:1). Today a row shows only a name, so two tasks are indistinguishable. Every field here already ships on the Task the board is already fetching: updatedAt, git_branch, tags, needs_human_review, last_finish_reason. Zero new data.
4
Actions on hover, not permanent. Today pin/rename/delete are pinned at 60 % opacity on all 110 rows — that is 330 icons of permanent noise, and the eye reads them before the text. Proposed: opacity-0 → opacity-100 on :hover and :focus-within, so the resting state is pure text. Keyboard users keep access via focus-within.
5
Hairline separators. A 1 px #282727 line between rows. Without it a 32 px row block is one solid rectangle; with it the group is countable at a glance and your eye can track a column downward.
6
Group header promoted to a section label. Uppercase, 12 px, letter-spacing .07em, with a real bottom border. Today the column name is 14 px font-medium sentence case — the same visual weight as a task name, so nothing says "this is a heading".
7
Count badge strengthened. 11 px font-600 on #a6a69c instead of 12 px on #7a8382 — 110+ was nearly invisible; a count is the fastest way to size a group before expanding it.
8
Column description un-truncated. Today 11 px with truncate → one clipped line. Proposed 12 px / #a6a69c, wraps to 2 lines. These descriptions are the board's rules ("only human puts the task here") and clipping them hides exactly the part that matters.
9
Compact density toggle. A Comfortable ⇄ Compact switch. Compact hides the metadata line and drops to 12.5 px / 28 px rows. Persisted in localStorage like the existing collapse state, because 110 rows of two-line records is a real scroll for some people and not for others.

The two failing rows are the real argument for this change. A 12 px body label at 4.38:1 and a 110+ count at 2.79:1 are the two things your eye hits most on this screen, and both are below AA. The proposed values clear it without touching the palette — the tokens already exist in style.css (--semantic-text, --semantic-text-muted).

What changes, and what does not

Files touched

  • KanbanTaskRow.vue — owns its layout. It currently just wraps the shared sidebar row; the redesign makes it a real row component that still reuses the useTaskActions contract.
  • KanbanRowView.vue — group header, description, density prop threading.
  • KanbanView.vue — pass density through (localStorage).
  • KanbanRowView.spec.ts / KanbanView.rowMode.spec.ts — extend.

Explicitly not changing

  • Not WorkspaceItemTaskRow.vue — the sidebar's shared row has 3 spec files and its own density. Styling the kanban row through it would regress the sidebar.
  • Not the column-mode card. The card is a different job (moving work) at a different density.
  • Not any data-testid or emit name — all 3 kanban row specs and the urlPreservation / sortByApi specs key off them.
  • Not the backend, the API, or the DB. No new endpoint, no migration.

The one judgement call I want your read on: going from 32 px to ~46 px rows is a 44 % density drop. That is right for todo (2 rows) and wrong for merged (110 rows) — which is exactly why callout 9 adds the Compact toggle. If you'd rather not add a control, the alternative is to keep the metadata line but let the group collapse do the work — merged starts collapsed by default. Say which you prefer and I'll implement it.
